# 新建剪辑页案例缩略图设计

## 背景

新建剪辑页的“快速体验”区域需要同时展示乒乓球和羽毛球两个内置案例。案例入口参考 RestCut 自动剪辑页面，使用可点击的视频缩略图，不在缩略图卡片内叠加标题、时长等文本。

## 目标

- 在新建剪辑页展示乒乓球、羽毛球两个案例缩略图。
- 两个缩略图都可点击，并继续进入各自运动类型的剪辑配置流程。
- 保留“快速体验”区域本身的标题和说明文字。
- 保留现有缩略图抽帧、缓存和失败占位逻辑。

## 非目标

- 不改变案例视频资源、案例配置或剪辑流程。
- 不新增静态缩略图资源。
- 不重构通用 `DemoVideoPicker` 文字按钮组件。

## 方案

继续复用 `demoVideos` 数据源和现有 `_DemoThumbnail` 组件。新建剪辑页通过横向 `Row` 渲染两个等宽的 16:9 缩略图，外层保留 `TpHover` 的点击反馈与禁用加载状态。移除当前缩略图上的标题角标、时长角标以及仅服务于角标的文本样式变量。

案例点击后的 `_startDemoClip` 流程不变：将对应资源物化到本地，按 `sportTypeKey` 选择运动类型和默认配置，创建本地视频记录并跳转到视频剪辑配置页。

## 数据流与错误处理

```text
demoVideos
    ├─ ping_pong_demo ─┐
    └─ badminton_demo ─┴─> _buildDemoCard -> _DemoThumbnail
                                      │
                                      └─ tap -> _startDemoClip -> 配置页
```

缩略图仍由演示视频服务物化后使用 FFmpeg 抽帧，并按案例 ID 缓存。抽帧过程中显示加载占位图，失败时显示摄像机图标占位图。点击案例时沿用页面级 `_demoLoading`，防止重复启动；处理失败继续通过现有错误提示反馈。

## 测试与验收

- 静态检查 `demoVideos` 中的两个案例仍被渲染。
- 验证页面代码不再为案例构建标题/时长角标。
- 运行 `dart format`、`flutter analyze` 和相关 Flutter 测试。
- 手动验收：新建剪辑页显示两个并排缩略图；点击任一缩略图都进入对应剪辑配置页；缩略图加载失败时仍有占位反馈。
